==========================================================================
 SPARTUM — MAPEADO DEL CÓDIGO POR ÁREAS
==========================================================================
Guía rápida de "dónde está cada cosa". Rutas relativas a la raíz del
proyecto. Arquitectura: MVC casero en PHP puro.
  Petición -> index.php (front controller) -> routers/web.php (Bramus
  Router) -> app/controladores/* -> app/modelos/* (PDO/MariaDB) -> vistas
  en app/vistas/*.

Índice:
  1. STRIPE (pagos)
  2. VIEW TRANSITION (transición entre páginas + animaciones)
  3. CSS (estilos y temas)
  4. MAQUETACIÓN (layouts, vistas y parciales)
  5. CLASES (arquitectura POO: controladores y modelos)
  6. RUTAS (enrutado)
  7. EXTRAS (seguridad, sesión, validación, correo, BD, JS, config...)


==========================================================================
 1. STRIPE  (pasarela de pago de suscripciones)
==========================================================================
SDK (dependencia):
  - composer.json / composer.lock ...... stripe/stripe-php ^19.4
  - vendor/stripe/ ..................... SDK instalado (no versionado)

Claves (entorno, NO en git):
  - .claves ............................ claves de prueba de Stripe (test)
  - env / .env ......................... STRIPE_SECRET_KEY, STRIPE_PUBLISHABLE_KEY
    (STRIPE_SECRET_KEY = clave secreta servidor; STRIPE_PUBLISHABLE_KEY =
     clave pública cliente)

Backend (servidor):
  - app/controladores/PagoControlador.php
      · index()             -> muestra la página de pago
      · crearIntentoPago()  -> \Stripe\Stripe::setApiKey(...) +
                               \Stripe\PaymentIntent::create([...])  (~línea 149)
                               devuelve clientSecret en JSON
      · exito()             -> \Stripe\PaymentIntent::retrieve(...) (~línea 217),
                               confirma pago y activa/renueva la suscripción
      · cancelado()         -> pago cancelado

Frontend (cliente):
  - app/vistas/frontend/pago/pagar.php
      · <script src="https://js.stripe.com/v3/">  (Stripe.js)
      · Stripe(<publishable key>) + elements.create('payment') +
        stripe.confirmPayment({...})
  - app/vistas/frontend/pago/exito.php ...... pantalla de éxito
  - app/vistas/frontend/pago/cancelado.php .. pantalla de cancelado

Modelos relacionados con la suscripción comprada:
  - app/modelos/susbscripcion.php .......... catálogo de planes (precio, etc.)
  - app/modelos/cliente_subscripcion.php ... alta/estado de la suscripción del cliente

Rutas (ver routers/web.php):
  - GET  /pago               -> PagoControlador@index
  - POST /pago/crear-intento -> PagoControlador@crearIntentoPago
  - GET  /pago/exito         -> PagoControlador@exito
  - GET  /pago/cancelado     -> PagoControlador@cancelado

 2. VIEW TRANSITION  (transición de página "cortina + logo" y animaciones)
==========================================================================
NOTA: no usa la View Transitions API nativa del navegador; es una
transición propia hecha con GSAP + CSS (comentada así en el código).

Motor de animación:
  - public/assets/js/vendor/gsap.min.js ..... librería GSAP (tweens)

Transición entre páginas (efecto cortina):
  - public/assets/js/gp-page-transition.js .. lógica completa:
      crea #gp-page-curtain (__top/__bottom/__logo), intercepta clics en
      enlaces internos, timelines GSAP de cierre/apertura, precarga la
      página destino con iframe oculto y bloquea el scroll.
      Expone window.gpNavigateWithTransition.
  - app/vistas/layouts/partials/gp_page_transition_boot.php
      se incluye en el <head> (frontend/admin header, línea 11); pinta la
      cortina al instante (clase gp-nav-curtain-hold) para evitar parpadeos.

Animación de entrada del panel (dashboard "bento"):
  - public/assets/js/gp-gsap-motion.js ...... gsap.from() con stagger sobre
      .gp-bento-tile (aparecen con fade + desplazamiento).

Banners flash (avisos éxito/error):
  - public/assets/js/gp-flash-banner.js ..... mostrar/ocultar con transición.

Animaciones en CSS (public/assets/css/app-theme.css):
  - @keyframes gp-page-fade-in (~2854)  + .gp-page-enter
  - @keyframes gp-flash-in (~3029) / gp-flash-out (~3041)
  - #gp-page-curtain y .gp-page-curtain__top/__bottom/__logo (~2873-2942)
  - numerosas reglas transition: (hover de botones, tarjetas, menús...)
  - public/assets/css/style.css: @keyframes loader (~215) spinner plantilla

Carga de los scripts (orden, con defer):
  - app/vistas/layouts/frontend/footer.php  (~102-105)
  - app/vistas/layouts/admin/footer.php     (~31-34)

Accesibilidad:
  - Respetan prefers-reduced-motion en JS (prefersReducedMotion()) y en CSS
    (@media (prefers-reduced-motion: reduce) en app-theme.css ~2079/2866/3121).

Librerías de animación de la landing pública (jQuery), init en:
  - public/assets/js/main.js ... owlCarousel (carruseles), barfiller
      (barras de progreso), magnificPopup (popups img/vídeo), slicknav
      (menú móvil).

 6. RUTAS  (enrutado)
==========================================================================
Front controller:
  - index.php ....... arranca sesión/seguridad e inicia el Router de Bramus
  - router.php ...... arranque para el servidor integrado de PHP (php -S)

Definición de rutas:
  - routers/web.php . TODAS las rutas. Helper controller($router, metodo,
      ruta, 'Controlador@metodo') que además valida CSRF en POST.
  Grupos de rutas: inicio, login/registro, recuperación/reactivación,
      cuenta/perfil, admin (clientes, monitores, fisios, suscripciones,
      actividades, solicitudes, feedback, seguridad, tickets), monitor,
      salas/materiales, actividades/inscripciones, fisioterapia, pago.

Librería de enrutado:
  - bramus/router (composer) + helpers de base path en core/helpers/url.php
    (app_base_path, url(), asset(), router_server_base_path())

404:
  - $router->set404(...) en index.php -> ErrorControlador@notFound
